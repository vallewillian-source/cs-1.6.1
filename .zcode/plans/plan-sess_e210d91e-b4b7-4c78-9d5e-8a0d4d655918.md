# V1 — Bots algoritmo + Jev (só de_dust2, sem over-engineering)

## Objetivo
No servidor dedicado local (dust2 defuse), um **sidecar Python** consulta o **Jev (TypeSafe)** e escolhe, por time e em português de tática, uma **intent de um conjunto fechado**; a DLL (`cs.so`) aplica a intent aos bots do CCSBot existente. O CCSBot continua sendo o "músculo" (nav, visão, mira, armas, combate); o Jev é o "cérebro lento". VR e flat ficam idênticos, porque bots vivem no servidor.

## Arquitetura
```
servidor (podman, 32-bit)                 host (Python)
┌─────────────────────────────┐          ┌──────────────────────────┐
│ cs.so (ReGameDLL)           │  arquivo │ tools/botbrain/botbrain.py│
│  CCSBot (músculo)           │  mailbox │  1. poll observe_<t>.txt │
│  cs_bot_advisor.so ────────►│ observe  │  2. monta state (o "DOM") │
│    · escreve observe_<t>.txt│─────────►│  3. Jev /v1/systemone     │
│    · lê plan_<t>.txt ◄──────│ plan     │     choice ∈ intents      │
│    · aplica intent nos bots │◄─────────│  4. escreve plan_<t>.txt  │
└─────────────────────────────┘          │  cache + trace JSON       │
      cstrike/advisor/                    └──────────────────────────┘
```

## Componentes e arquivos

### A. DLL (ReGameDLL_CS) — edições mínimas
Novos:
- `regamedll/dlls/bot/advisor/cs_bot_advisor.h` / `.cpp` — cvars, mailbox (leitura/escrita `key=value`), detecção de rodada/eventos, mapa intent→comportamento, log.
- Adicionar o `.cpp` à **lista fixa** em `regamedll/CMakeLists.txt` (junto de `dlls/bot/cs_bot_*.cpp`).

Edições cirúrgicas em arquivos existentes:
1. `dlls/bot/cs_bot_manager.cpp` — em `CCSBotManager::RestartRound()` chamar `Advisor_OnRoundStart()`; no fim de `CCSBotManager::StartFrame()` chamar `Advisor_FrameUpdate()` (poll do `plan` + detecção de eventos: bomba plantada, time reduzido a 1 vivo, heartbeat).
2. `dlls/bot/cs_bot_update.cpp` — **uma** chamada `Advisor_ApplyIntent(this)` imediatamente antes do dispatch da máquina de estados (linha ~772, `if (m_isAttacking) m_attackState.OnUpdate(this); else m_state->OnUpdate(this);`). É o seam recomendado: aplica a intent **uma vez por mudança** (idempotente) e deixa o CCSBot conduzir o resto, inclusive o combate.
3. `dlls/bot/cs_bot.h` — 3 membros novos: `int m_advisorIntent; float m_advisorIntentTs; bool m_advisorApplied;`.
4. `dlls/bot/cs_bot_init.cpp` — registrar cvars do advisor em `Bot_RegisterCVars()`.

Cvars: `advisor_enable` (0/1), `advisor_dir` (default `advisor`), `advisor_debug` (0/1), `advisor_force_intent <nome>` (injeta intent sem o sidecar — testa a metade DLL isolada).

### B. Conjunto fechado de intents (V1, defuse/dust2)
Offense (T): `RUSH_B`, `RUSH_A_LONG`, `RUSH_A_SHORT`, `SPLIT_A`, `ECO_SAVE`, `HOLD_AFTER_PLANT`, `DEFAULT`.
Defense (CT): `STACK_A`, `STACK_B`, `ECO_SAVE`, `RETAKE_A`, `RETAKE_B`, `DEFAULT`.

Mapeamento **sem coordenadas inventadas** (usa o que o mapa já dá): `TheCSBots()->GetZone(i)->m_center` (centros de A/B derivados do BSP) e `GetRandomAreaInZone()`/`GetRandomPositionInZone()` para espalhar os bots. Ex.: `RUSH_B` → cada T recebe `MoveTo(zoneB->m_center)` com posição aleatória dentro da zona, carrier com `SetTask(PLANT_BOMB)`, `SetDisposition(ENGAGE_AND_INVESTIGATE)`; `STACK_B` → CT `Hide(zoneB)` + `SetTask(GUARD_BOMB_ZONE)`; `ECO_SAVE` → `SetDisposition(IGNORE_ENEMIES)` e recuo para a própria zona; `RETAKE_*` → `MoveTo(zona plantada)`. `DEFAULT` = **não sobrescreve nada** (comportamento stock, que também é o fallback).

### C. Sidecar Python — `tools/botbrain/`
- `botbrain.py` — loop do daemon (poll do observe → Jev → escreve plan; cache por assinatura; trace JSON por decisão).
- `typesafe.py` — cópia mínima e provada do cliente do clone: `post_json()` + validação de `choice` (mesmo protocolo `state`+`questions`→`answers`, `Authorization: Bearer`, retry 429/529/503) de `jev_ultrafast/model.py`. Lê `TYPESAFE_API_KEY`/`TYPESAFE_MODEL` de `~/Workspace/jev-ultrafast/.env`. **Não** modifica o clone.
- `intents.py` — critérios (descrição de cada intent) + regras de coach (conservador em eco, preferir site não usado, adaptar a placar).
- `cache.py` — assinatura `(placar, economia, vivos, fase, zona, histórico)` → plano; persistida em JSON.
- `run.sh` — carrega o `.env` e sobe o daemon. `README.md`.

### D. Protocolo (arquivos, `key=value` — sem parser JSON no C++)
`cstrike/advisor/observe_<team>.txt` (DLL escreve): `v, ts, team, phase(freeze|live|postplant), round, score_us, score_them, alive_us, alive_them, money_avg_us, bomb(carried|planted|dropped|none), bomb_zone(A|B|none), site_last, history`.
`cstrike/advisor/plan_<team>.txt` (sidecar escreve): `v, ts, intent, aggression, source(jev|cache)`.
Escrita atômica (tmp + rename). DLL nunca bloqueia: o plan é aplicado quando o mtime muda; sem plano novo, mantém o anterior (ou stock).

### E. Config e build
- `scripts/build-regamedll.sh` — build 32-bit do `cs.so` no container podman `steamcmd/steamcmd` (espelhando `build-cs16.sh`), copiando para `server/cstrike/dlls/cs.so`.
- Copiar `BotProfile.db` + `BotChatter.db` (`src/cs16-client/3rdparty/cs16client-extras/`) para `server/cstrike/` — **sem isso os bots não spawnam**.
- `server/cstrike/advisor.cfg` — `bot_quota 8`, `bot_add_t`×4, `bot_add_ct`×4, `mp_autoteambalance 0`, `mp_limitteams 0`, `advisor_enable 1`, `advisor_dir advisor`; exec'ado pelo launcher.
- `scripts/run-botbrain.sh` — sobe sidecar + servidor em dust2 juntos (não toca no `run-server.sh` atual).

## Fases (ordem de implementação)

**Fase 0 — Gate de navegação (bloqueante).** Build do `cs.so` atual (sem advisor), copiar os `.db`, subir dust2, `bot_quota 8`, verificar se os bots andam. Se não houver nav: `bot_nav_analyze` + `bot_nav_save` → gerar `server/cstrike/maps/de_dust2.nav` e confirmar pathfinding. *Se isso falhar, o V1 inteiro muda de forma — por isso é a primeira coisa.*

**Fase 1 — Mailbox e observação (sem LLM).** Módulo `cs_bot_advisor` + cvars + escrita do `observe_<team>.txt` no round start e em eventos. Verificação: o arquivo aparece com os fatos corretos.

**Fase 2 — Aplicação da intent.** Mapa intent→comportamento + hook em `cs_bot_update.cpp`. Verificação isolada com `advisor_force_intent RUSH_B`: os T convergem para B; `STACK_B`: os CT se agrupam em B; `advisor_enable 0`: idêntico ao stock.

**Fase 3 — Sidecar + Jev.** `tools/botbrain/` ligando o loop completo com TypeSafe, cache e trace. Verificação: log mostra observe→choice→plan→aplicado, a intent varia com placar/economia, e a 2ª rodada idêntica vem de `source=cache`.

**Fase 4 — Eventos de meio de rodada.** Re-observação e re-plan em bomba plantada e em clutch (1 vivo), com `RETAKE_*`/`HOLD_AFTER_PLANT`.

**Fase 5 — Docs e fechamento.** `docs/BOTBRAIN.md` (arquitetura, protocolo, cvars, como rodar/depurar) + entrada no `PLAN.md`/`README.md`.

## Verificação (tudo headless — não precisa de humano nem headset)
Como o servidor é dedicado e os bots jogam sozinhos, cada fase é provada por log: regressão (`advisor_enable 0`), canal de intent (`advisor_force_intent`), laço Jev (trace dos dois lados), cache (2ª rodada), e eventos (plant/clutch no log). Screenshot não é necessário.

## Riscos e mitigação
1. **Nav de dust2 ausente (maior):** gerar e commitar `de_dust2.nav`; provado na Fase 0 antes de qualquer código de IA.
2. **`BotProfile.db` ausente no servidor:** copiar os DBs (Fase 0).
3. **Build 32-bit:** espelhar a receita já validada do container `steamcmd` via podman.
4. **Latência/custo do TypeSafe:** decisão no freeze (4 s escondem a latência), cache por assinatura, fallback para o stock.
5. **Permissões de arquivo (container root):** podman rootless mapeia root→uid do host; DLL escreve só `observe_*`, sidecar só `plan_*` (sem conflito de escrita).
6. **`mp_autoteambalance`/`limitteams` atrapalhando:** zerados no `advisor.cfg`.
